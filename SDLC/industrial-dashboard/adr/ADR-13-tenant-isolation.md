# ADR-13 — Tenant isolation: scoped repositories + FORCE RLS + composite FKs + split DB roles

Status: **Accepted** · Applies to: every table that holds customer data

## Decision summary

Tenant isolation is enforced by **three independent layers**. A bug in one must not leak data:

1. **Application scope**:
   - The organization comes **only** from the path (`/api/v1/orgs/{org_id}/…`), checked against the caller's membership.
   - It never comes from the request body or an MQTT payload.
   - A non-member gets **404** (existence is not revealed). A resource id outside the scope also gets **404**.
2. **Postgres Row-Level Security**, fail-closed, `FORCE`d, keyed on a transaction-local setting.
3. **Schema integrity**: composite foreign keys make cross-tenant relationships impossible to store.

## 1. Database roles

| Role | Login | Owns tables | BYPASSRLS | Grants | Used by |
|---|---|---|---|---|---|
| `wds_owner` | only from the `migrate` job | yes | no | DDL | Alembic |
| `wds_app` | yes | no | **no** | SELECT/INSERT/UPDATE/DELETE on tenant tables; INSERT/SELECT only on `audit_log`, `command_events` | API request path |
| `wds_system` | yes | no | **no** | same as `wds_app` + SELECT on `edges` across orgs via a dedicated policy (§3.3) | ingest, outbox relay, sweeper, MQTT reconciler |

- Superuser credentials are only in the postgres container env, used by `init` to create roles. Neither app container receives them.
- Tests run as `wds_app` / `wds_system`. **No isolation test may connect as superuser or owner.**

## 2. Setting the tenant context

- There is exactly one function, `db.session.tenant_tx(conn, org_id)`. It runs `BEGIN; SELECT set_config('app.org_id', $1, true);` — the third argument makes it transaction-local, so it behaves like `SET LOCAL`. Then it yields, then COMMIT/ROLLBACK.
- The setting disappears at the end of the transaction, so a pooled connection cannot carry a tenant into the next request.
- Defense in depth: the pool runs `RESET ALL` on connection check-in.
- `tests/tenancy/test_rls.py::test_single_call_site` asserts that the literal `set_config('app.org_id'` appears in exactly one source file.
- There is no autocommit path for tenant tables. Repository functions take a `TenantConn` type that can only be created by `tenant_tx`.

## 3. Policies

For every tenant table `T`:

```sql
ALTER TABLE T ENABLE ROW LEVEL SECURITY;
ALTER TABLE T FORCE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON T
  USING      (org_id = NULLIF(current_setting('app.org_id', true), '')::uuid)
  WITH CHECK (org_id = NULLIF(current_setting('app.org_id', true), '')::uuid);
```

- Context not set → `current_setting(..., true)` returns NULL. Context empty → NULLIF gives NULL. In both cases the predicate is NULL, so **0 rows** are visible and **INSERT/UPDATE fail**. This is fail-closed.
- §3.3 `wds_system` reads `edges` to map MQTT topic → org **before** any context exists: `CREATE POLICY edge_lookup ON edges FOR SELECT TO wds_system USING (true)`.
  - `wds_system` holds **column-level** `SELECT (id, org_id, site_id, status, mqtt_username, credential_version)` only. It has no SELECT on any other edge column, and no write on edges outside `tenant_tx`.
  - Every other worker write goes through `tenant_tx` with the org resolved from this lookup.
  - The topic's `org_id`/`site_id` must equal the looked-up row. Otherwise the message is dropped as a security event.
- Global tables without `org_id` (`users`, `revoked_sessions`) have no tenant data. They are reachable only through specific repository functions. `wds_app` gets no SELECT on other users' rows beyond what membership queries join.

## 4. Composite foreign keys

Every parent has `UNIQUE (org_id, id)`. Every child carries `org_id` and references the pair:

```
organizations(id)
sites        (org_id, id)  FK (org_id)            → organizations(id)
lines        (org_id, id)  FK (org_id, site_id)   → sites(org_id, id)
edges        (org_id, id)  FK (org_id, site_id)   → sites(org_id, id)
devices      (org_id, id)  FK (org_id, line_id)   → lines(org_id, id)
tags         (org_id, id)  FK (org_id, site_id)   → sites(org_id, id)
                           FK (org_id, edge_id)   → edges(org_id, id)
tag_latest   (org_id, tag_id) FK → tags(org_id, id)
tag_history  (org_id, tag_id, ts) FK → tags(org_id, id)
alarm_rules  (org_id, id)  FK (org_id, tag_id)    → tags(org_id, id)
alarms       (org_id, id)  FK (org_id, tag_id)    → tags(org_id, id)
commands     (org_id, id)  FK (org_id, tag_id)    → tags(org_id, id)
command_events, command_outbox  FK (org_id, command_id) → commands(org_id, id)
memberships  (org_id, user_id)  FK (org_id) → organizations(id); user_id → users(id)
invites      (org_id, id)
audit_log    (org_id, id)
```

A row that links a tag of org B to a site of org A violates the FK, regardless of application bugs.

## 5. Identifiers

- All primary keys are UUIDv7 generated by the application. URLs, MQTT topics and APIs use ids only.
- Slugs and names are mutable display fields. They never appear in authorization or in topics.

## 6. What this does **not** protect against

- RLS keyed on `app.org_id` stops queries that **forgot** tenant scoping. It does **not** stop an attacker who can run arbitrary SQL as `wds_app`, because that attacker can call `set_config` themselves.
- Mitigations:
  - least-privilege grants: no DDL, no `audit_log` UPDATE/DELETE, no BYPASSRLS, no superuser in app containers;
  - DB credentials only in the backend env;
  - the postgres port is not published to the host and is reachable only on the compose network;
  - security event logging.
- Escalation triggers (future ADR): role-per-tenant or database-per-tenant if (a) a regulated customer requires it or (b) any tenant needs separate encryption keys.

## 7. Required tests (phase 2 exit gate)

| Test | Assertion |
|---|---|
| `test_rls.py::test_no_context_no_rows` | as `wds_app` without `tenant_tx` → SELECT returns 0, INSERT raises |
| `test_rls.py::test_empty_context_no_rows` | `set_config('app.org_id','',true)` → 0 rows |
| `test_rls.py::test_pool_reuse_no_leak` | pool max_size=1: tx(org A) then a bare query → 0 rows; tx(org B) never sees A |
| `test_rls.py::test_force_rls_blocks_owner_path` | `relforcerowsecurity` true for every tenant table (catalog check: no table forgotten) |
| `test_rls.py::test_single_call_site` | exactly one `set_config('app.org_id'` in source |
| `test_rls.py::test_roles_not_bypass` | `wds_app`, `wds_system` have `rolbypassrls=false`, `rolsuper=false`, own no tables |
| `test_schema.py::test_composite_fk_rejects_cross_tenant` | inserting a tag with site of A and org B → FK violation |
| `test_isolation.py` (HTTP) | user of A on every `/orgs/{B}/…` route and every B resource id → 404; list endpoints never include B rows; WS auth for B's site → 4403 |

## 8. Implementation note (v4 T9, 2026-10-13)

The path-org routing described in §1 is now live on `ui-v4`:
`_v2_org()`/`_v2_scope()` in `backend/app/main.py` resolve `/api/v1/orgs/{org}`
to a UUID, then check the principal's memberships (`_effective_org_roles`) —
non-member **and** non-existent org both return 404. The v1 `/api/*` surface
remains as a compat shim pinned to the seeded org through `v1_tx()` — the
only place an org id is still global.

Two deliberate deviations from this ADR's phase-2 wording:

- **`wds_system` org enumeration**: §3.3 mentions only the `edges` pre-context
  lookup. T9 adds `system_org_list` (`active_org_ids()` in `db/context.py`) —
  a SELECT on `organizations(id, deleted_at)` only — so sweeps (registry
  refresh, alarm rules, insight passes, command restart sweep) can visit
  every tenant without a hard-coded list. Column-limited like the edge view.
- **v1 MQTT topics**: the plan's "v1 devices map to seeded org" is realized
  as *rejected at the broker* — dynsec provisions only v2 ACLs since T6, so
  no v1 topic can reach ingest; ingest itself drops non-v2 topics as
  `mqtt_bad_topic` defense-in-depth.

HTTP-level evidence: `tests/integration/test_tenancy.py` (two orgs, real
routes, cross-org 404s, per-role 403s, `/ws/v1` site scoping, and a second
org's provisioned edge publishing telemetry that lands only in that org).
