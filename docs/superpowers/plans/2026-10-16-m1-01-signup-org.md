# M1-01: Sign-up, Create Org, Org Switcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new person can sign up, verify email, create an organization (becoming `owner` with a default site), switch between their orgs, and the console reads and writes the *active* org's data instead of the single seeded v1 org.

**Architecture:** Backend adds `POST /api/v1/orgs` (verified-email gate, slug, default site, owner membership, all in one tenant transaction) and org settings columns. The web gains an `activeOrg` store; live reads (`tags`, `alarms`, `commands`, `alarm-rules`, WebSocket) move from the v1 compat shim to `/api/v1/orgs/{org}/sites/{site}/…` and `/ws/v1`. Sign-up itself is Keycloak self-registration (realm flags already set in the prod realm; dev realm gets the same flags, without email verification because dev has no SMTP).

**Tech Stack:** FastAPI + asyncpg (RLS via `tenant_tx`), Alembic raw SQL twins, React + Vite + bun, Keycloak 26.4, pytest (`contract`, `tenancy`, `integration`).

**Spec:** `docs/superpowers/specs/2026-10-16-saas-launch-roadmap.md` §5 items 1.1, 1.2; §14 (UX rules U1, U4, U5, U10).

## Global Constraints

- `POST /api/v1/orgs` creates the org, makes the creator `owner`, creates a default site (roadmap 1.2).
- Org slug is unique and URL-safe; timezone and language (`th`/`en`) are set at creation (1.2).
- Email verification is required before an org can be created; an unverified user cannot reach any org data (1.1).
- Non-member or non-existent org → 404, identical response (existing `_v2_org` rule).
- Every new table/column keeps fail-closed RLS; `tests/tenancy/test_rls_coverage.py` stays green.
- Thai and English strings for every new UI string (U10); tokens only, no raw hex (U2).
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- Two concurrent `POST /orgs` with the same slug: exactly one 201, the other 409 `slug_taken` (DB unique index decides, not a pre-check).
- Slug input like `Acme Plant!`, `-x`, `a`*200, unicode, or reserved words (`admin`, `api`, `new`): rejected with 422 or normalized as documented, never stored raw.
- A creator's `/me` right after creation shows the new org without waiting for `AUTHZ_TTL_S` (cache invalidated).
- A user with 0 orgs reloading the page: lands on "Create organization", not the denied wall.
- Switching org while a WebSocket is open: old subscription closed, no values from the previous org rendered.
- A viewer calling `POST /orgs` is fine (any verified user may create their own org); it must not touch other orgs they belong to.
